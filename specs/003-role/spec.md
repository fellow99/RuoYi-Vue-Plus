# 角色管理功能规格 (spec.md)

> 模块：003-role | 状态：已实现 | 最后更新：2026-08-10

## 1. 模块概述

### 1.1 目的
角色管理模块负责管理系统中的 RBAC 角色，包括角色本身的 CRUD、菜单权限分配、数据范围权限配置，以及用户与角色的关联管理。角色是权限体系的枢纽，连接用户与菜单权限、数据权限。

### 1.2 解决的问题
- 管理员需要定义不同的角色（如超级管理员、普通用户、部门主管）来控制系统访问范围
- 每个角色需要分配不同的菜单权限（能看到哪些页面、操作哪些按钮）
- 每个角色需要配置数据范围（如"只能看本部门数据"还是"全部数据"）
- 需要将用户分配到角色，实现用户 → 角色 → 权限的链式授权

### 1.3 范围
- ✅ 角色 CRUD（分页查询、新增、修改基本信息、修改状态、删除）
- ✅ 角色菜单权限分配（sys_role_menu 关联表）
- ✅ 角色数据范围权限分配（sys_role_dept 关联表，支持 6 种数据范围）
- ✅ 角色与用户关联（批量授权、取消授权）
- ✅ 角色导出 Excel
- ✅ 角色操作后踢出相关在线用户（刷新权限）
- ✅ 超级管理员角色保护（不允许操作超级管理员角色）
- ❌ 角色本身没有审批流程
- ❌ 不涉及用户注册时自动分配角色

## 2. 用户故事
- 作为**管理员**，我可以新增角色并设置角色标识符（roleKey），以便在代码中通过注解控制权限
- 作为**管理员**，我可以为角色分配菜单权限（目录/菜单/按钮），以便拥有该角色的用户看到对应页面
- 作为**管理员**，我可以为角色配置数据范围（全部/自定义/本部门/本部门及以下/仅本人/部门及以下或本人），以便控制用户能查看哪些数据
- 作为**管理员**，我可以批量选择用户授予或取消角色，以便快速调整人员权限
- 作为**管理员**，我可以禁用某个角色，系统会自动踢出所有拥有该角色的在线用户

## 3. 功能需求

- FR-003-001: 系统 MUST 支持分页查询角色列表，支持按角色名称、角色权限字符串、状态、创建时间范围筛选
- FR-003-002: 系统 MUST 支持新增角色，必填项包括角色名称（≤30字符）、角色权限字符串（≤100字符）、显示顺序
- FR-003-003: 系统 MUST 支持修改角色基础信息（名称、权限字符串、排序、状态、备注），不触及菜单和数据权限
- FR-003-004: 系统 MUST 支持修改角色权限信息（菜单权限 + 数据权限），采用先删后增策略更新关联数据
- FR-003-005: 系统 MUST 支持修改角色状态（正常/停用），状态变更时踢出该角色的所有在线用户
- FR-003-006: 系统 MUST 支持批量删除角色，删除时同时清理角色-菜单、角色-部门关联
- FR-003-007: 系统 MUST 禁止操作超级管理员角色（roleId=1, roleKey=superadmin），包括修改、删除、修改权限标识符
- FR-003-008: 系统 MUST 支持导出角色列表为 Excel
- FR-003-009: 系统 MUST 支持查询已分配和未分配某角色的用户列表（分页）
- FR-003-010: 系统 MUST 支持批量授权用户到角色
- FR-003-011: 系统 MUST 支持单个取消授权和批量取消授权用户
- FR-003-012: 系统 MUST 支持 6 种数据范围权限：全部数据权限、自定数据权限、本部门数据权限、本部门及以下数据权限、仅本人数据权限、部门及以下或本人数据权限
- FR-003-013: 系统 MUST 在校验角色数据范围时，通过 @DataPermission 注解按创建部门和创建人过滤非管理员可见的角色列表
- FR-003-014: 系统 MUST 支持菜单树父子关联显示控制（menuCheckStrictly）和部门树父子关联显示控制（deptCheckStrictly）
- FR-003-015: 系统 MUST 在角色修改（基本信息/权限/状态）后发布 OnlineUserCleanEvent 事件踢出相关在线用户

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| SysRole | 角色主表 | roleId, roleName, roleKey, roleSort, dataScope, status |
| SysRoleMenu | 角色-菜单关联 | roleId, menuId |
| SysRoleDept | 角色-部门关联（数据权限） | roleId, deptId |
| SysUserRole | 用户-角色关联 | userId, roleId |

## 5. 验收场景

### 场景：新增角色并分配菜单权限
- Given 管理员登录系统，打开角色管理页面
- When 填写角色名称"测试角色"、权限字符"test"、选择菜单权限树 → 提交
- Then 角色创建成功，拥有该角色的用户登录后仅能看到分配的菜单

### 场景：超级管理员角色不可操作
- Given 管理员登录系统
- When 尝试修改、删除超级管理员角色（roleId=1）
- Then 系统返回错误提示"不允许操作超级管理员角色"

### 场景：批量授权用户
- Given 管理员选中某角色，打开"分配用户"界面
- When 从"未分配用户列表"中勾选多个用户 → 点击批量授权
- Then 这些用户立即拥有该角色权限

### 场景：角色状态变更踢出在线用户
- Given 某角色下有在线用户
- When 管理员将该角色状态改为"停用"
- Then 拥有该角色的所有在线用户被强制登出

## 6. 非功能需求
- 角色修改操作 MUST 使用 @CacheEvict 清除 SYS_ROLE_CUSTOM 缓存
- 所有写操作 MUST 使用 @RepeatSubmit 防重复提交
- 操作日志 MUST 使用 @Log 注解记录，区分 INSERT/UPDATE/DELETE/EXPORT/GRANT 业务类型
- 角色数据权限校验 MUST 通过 @DataPermission 插件实现，使非管理员用户只能看到自己创建的角色

## 7. 依赖
- SysMenu（菜单管理）- 角色分配菜单权限时依赖菜单树
- SysDept（部门管理）- 角色数据权限配置依赖部门树
- SysUser（用户管理）- 角色关联用户
- OnlineUserCleanEvent - 角色变更后通知踢出在线用户
