# 岗位管理功能规格 (spec.md)

> 模块：005-post | 状态：已实现 | 最后更新：2026-08-10

## 1. 模块概述

### 1.1 目的
岗位管理模块负责维护系统中的岗位信息，岗位代表用户在组织内的具体职务（如总经理、部门经理、普通员工）。岗位与部门和用户关联，是多对多关系：一个部门可以有多个岗位，一个用户可以拥有多个岗位。

### 1.2 解决的问题
- 系统需要区分用户的具体职务，而不是仅靠部门来定位用户角色
- 岗位编码（postCode）可用于业务逻辑判断和权限细化
- 岗位列表支持按部门筛选，方便按组织维度查看人员配置

### 1.3 范围
- ✅ 岗位 CRUD（分页查询、新增、编辑、删除）
- ✅ 岗位与部门关联（一个岗位属于一个部门）
- ✅ 岗位与用户关联（通过 sys_user_post 多对多）
- ✅ 岗位名称唯一性校验
- ✅ 岗位编码唯一性校验
- ✅ 岗位导出 Excel
- ✅ 删除前置校验：已分配用户的岗位不允许删除
- ✅ 停用前置校验：已分配用户的岗位不允许停用
- ✅ 按部门筛选岗位的部门树选择器
- ❌ 岗位没有独立的权限控制（权限由角色和菜单控制）
- ❌ 岗位没有数据范围概念

## 2. 用户故事
- 作为**管理员**，我可以创建岗位（如"Java开发工程师"）并关联到"研发部"，以便在用户管理中分配岗位
- 作为**管理员**，我可以为岗位设置编码（如"java_dev"），以便在业务代码中通过岗位编码做逻辑判断
- 作为**管理员**，我可以在用户管理中将用户分配到多个岗位，以反映用户的多重职责
- 作为**管理员**，我可以通过部门树筛选查看某个部门下的所有岗位

## 3. 功能需求

- FR-005-001: 系统 MUST 支持分页查询岗位列表，支持按岗位名称、岗位编码、状态、部门ID筛选
- FR-005-002: 系统 MUST 支持新增岗位，必填项包括岗位名称、岗位编码、显示顺序
- FR-005-003: 系统 MUST 校验岗位名称唯一性（同部门下不可重名）
- FR-005-004: 系统 MUST 校验岗位编码唯一性（全局不可重复）
- FR-005-005: 系统 MUST 支持修改岗位信息（名称、编码、排序、状态、部门、类别编码）
- FR-005-006: 系统 MUST 在修改岗位状态为停用时校验：该岗位下不能有已分配用户
- FR-005-007: 系统 MUST 支持批量删除岗位
- FR-005-008: 系统 MUST 在删除岗位时校验：岗位不能被用户使用
- FR-005-009: 系统 MUST 支持导出岗位列表为 Excel
- FR-005-010: 系统 MUST 提供按部门 ID 统计岗位数量的接口（用于部门删除前的依赖检查）
- FR-005-011: 系统 MUST 支持通过用户 ID 查询该用户的所有岗位
- FR-005-012: 系统 MUST 提供岗位选择框列表，支持按岗位 ID 列表或部门 ID 筛选
- FR-005-013: 系统 MUST 通过 @DataPermission 注解按 dept_id 和 create_by 过滤岗位数据

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| SysPost | 岗位主表 | postId, postCode, postName, deptId, postSort, postCategory, status |
| SysUserPost | 用户-岗位关联 | userId, postId |

## 5. 验收场景

### 场景：新增岗位
- Given 管理员登录系统，打开岗位管理页面
- When 填写岗位名称"产品经理"、编码"product_mgr"、选择部门、排序 2 → 提交
- Then 岗位创建成功，在用户管理的岗位选择框中可见

### 场景：岗位编码重复
- Given 系统中已存在编码为"java_dev"的岗位
- When 管理员新增岗位并输入编码"java_dev"
- Then 系统返回"新增岗位'xxx'失败，岗位编码已存在"

### 场景：停用已分配用户的岗位
- Given 岗位"技术总监"下有 3 个已分配用户
- When 管理员将该岗位状态改为"停用"
- Then 系统返回"该岗位下存在已分配用户，不能禁用!"

### 场景：删除已被使用的岗位
- Given 岗位"项目经理"已被分配给多个用户
- When 管理员尝试删除该岗位
- Then 系统在校验阶段阻止删除

### 场景：按部门筛选岗位
- Given 管理员打开岗位列表，选择部门为"研发部"
- When 点击查询
- Then 列表仅显示属于"研发部"的岗位

## 6. 非功能需求
- 岗位的 postCode MUST 全局唯一，用于业务代码中的逻辑判断
- 所有写操作 MUST 使用 @RepeatSubmit 防重复提交
- 操作日志 MUST 使用 @Log 注解记录，区分 INSERT/UPDATE/DELETE/EXPORT 业务类型
- 岗位数据权限 MUST 通过 @DataPermission 插件按 dept_id 和 create_by 过滤

## 7. 依赖
- SysDept（部门管理）- 岗位关联部门，部门删除前需确认无岗位关联
- SysUser（用户管理）- 岗位关联用户，提供用户-岗位查询
