# 菜单管理功能规格 (spec.md)

> 模块：006-menu | 状态：已实现 | 最后更新：2026-08-10

## 1. 模块概述

### 1.1 目的
菜单管理模块负责维护系统的菜单/权限树，是前端路由和后端权限控制的桥梁。系统通过菜单定义前端页面路由、按钮权限标识，最终通过角色-菜单关联实现 RBAC 权限控制。

### 1.2 解决的问题
- 前端需要动态路由表来决定侧边栏菜单和页面访问权限
- 后端需要权限标识符（perms）来进行接口级别的权限校验（@SaCheckPermission）
- 管理员需要可视化地管理菜单树结构，包括目录、菜单、按钮三种类型
- 前端路由构建需要将数据库中的菜单记录转换成 Vue Router 格式

### 1.3 范围
- ✅ 菜单树形结构 CRUD（新增、编辑、删除、级联批量删除）
- ✅ 三种菜单类型：M（目录，仅作为分组容器）、C（菜单，对应前端页面）、F（按钮，权限标识）
- ✅ 路由配置：path、component、queryParam、isFrame（外链/内链）、isCache
- ✅ 权限标识（perms）：格式 `tool:build:list`，用于 @SaCheckPermission 注解
- ✅ 前端路由构建（RouterVo）：包含路由名称、路径、组件、Meta 信息、子路由
- ✅ 父子关联显示控制（menuCheckStrictly）
- ✅ 按用户 ID 查询可访问菜单（超级管理员看全部，普通用户按角色过滤）
- ✅ 按角色 ID 查询已授权的菜单 ID 列表
- ✅ 菜单权限批量查询（按角色列表）
- ✅ 路由名称和路径唯一性校验
- ✅ 只有超级管理员角色可以操作菜单（新增/编辑/删除）
- ❌ 普通用户不能管理菜单
- ❌ 菜单不参与数据权限过滤

## 2. 用户故事
- 作为**超级管理员**，我可以创建目录类型的菜单作为侧边栏分组，以便组织页面导航
- 作为**超级管理员**，我可以创建菜单类型的节点并配置路由路径和组件路径，以便前端能正确加载页面
- 作为**超级管理员**，我可以为菜单节点添加按钮类型的子节点（权限标识），以便在角色管理中精细控制按钮可见性
- 作为**前端开发者**，系统需要在用户登录后返回动态路由（RouterVo），以便前端根据路由表渲染侧边栏菜单
- 作为**后端开发者**，系统需要通过权限标识（perms）在接口上使用 @SaCheckPermission 进行权限校验

## 3. 功能需求

- FR-006-001: 系统 MUST 支持查询菜单列表（非树形），超级管理员看全部菜单，普通用户按角色过滤
- FR-006-002: 系统 MUST 支持查询菜单下拉树结构（用于新增/编辑菜单时选择父级菜单）
- FR-006-003: 系统 MUST 支持根据角色 ID 查询该角色已分配的菜单 ID 列表（用于角色权限分配回显）
- FR-006-004: 系统 MUST 支持三种菜单类型：M（目录）仅作为容器，C（菜单）对应 Vue 页面，F（按钮）作为权限标识
- FR-006-005: 系统 MUST 支持新增菜单，必填项包括菜单名称、菜单类型、显示顺序
- FR-006-006: 系统 MUST 在新增/编辑菜单时校验：菜单名称在相同父级下唯一
- FR-006-007: 系统 MUST 在新增/编辑菜单时校验：路由名称全局唯一，同级路由路径唯一，根目录下路径必须唯一
- FR-006-008: 系统 MUST 在新增/编辑菜单时校验外链（isFrame=Y）的 path 必须以 http(s):// 开头
- FR-006-009: 系统 MUST 在编辑菜单时校验：上级菜单不能选择自己
- FR-006-010: 系统 MUST 支持删除单个菜单，删除前校验无子菜单且无角色关联
- FR-006-011: 系统 MUST 支持级联批量删除菜单，同时清理角色-菜单关联数据
- FR-006-012: 系统 MUST 支持根据用户 ID 查询菜单树（仅目录和菜单类型），超级管理员返回全部，普通用户按角色过滤
- FR-006-013: 系统 MUST 支持将 SysMenu 列表构建为前端 RouterVo 格式，包含路由名、路径、组件、Meta、子路由
- FR-006-014: 系统 MUST 在构建 RouterVo 时：目录类型自动设置 alwaysShow=true 和 redirect="noRedirect"
- FR-006-015: 系统 MUST 在构建 RouterVo 时：外链菜单使用 INNER_LINK 组件包裹，内链域名特殊字符替换（`.` → `/`, `:` → `/`）
- FR-006-016: 系统 MUST 在构建 RouterVo 时：一级菜单的路由路径自动加 `/` 前缀
- FR-006-017: 系统 MUST 支持根据用户 ID 查询所有权限标识（perms）集合（用于 Sa-Token 登录时加载权限）
- FR-006-018: 系统 MUST 支持根据角色 ID 查询权限标识集合
- FR-006-019: 系统 MUST 支持根据角色 ID 列表批量查询权限标识映射（Map<roleId, Set<perms>>）
- FR-006-020: 系统 MUST 限制只有超级管理员角色可以新增、编辑、删除菜单

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| SysMenu | 菜单主表（自引用树） | menuId, parentId, menuName, menuType(M/C/F), path, component, perms, icon, isFrame, isCache, visible, status |
| SysRoleMenu | 角色-菜单关联 | roleId, menuId |
| RouterVo | 前端路由 VO | name, path, component, hidden, redirect, meta(MetaVo), children |
| MetaVo | 路由元信息 | title, icon, noCache, link, activeMenu |

## 5. 验收场景

### 场景：新增目录类型菜单
- Given 超级管理员登录系统，打开菜单管理
- When 点击新增 → 选择类型"目录"→ 填写名称"系统管理"、图标"system"、排序 1 → 提交
- Then 菜单树中出现新目录节点

### 场景：新增菜单类型节点
- Given 超级管理员选中"系统管理"目录节点
- When 点击新增 → 选择类型"菜单"→ 填写名称"用户管理"、路由"user"、组件"system/user/index"、权限标识"system:user:list" → 提交
- Then 创建成功，该菜单在角色权限分配树中可见

### 场景：新增按钮权限
- Given 超级管理员选中"用户管理"菜单节点
- When 点击新增 → 选择类型"按钮"→ 填写名称"新增用户"、权限标识"system:user:add" → 提交
- Then 创建成功，该按钮在角色权限分配树中可见，前端可根据权限标识控制按钮显示

### 场景：前端路由构建（RouterVo）
- Given 用户登录系统
- When 前端调用 /getRouters 接口
- Then 系统返回树形 RouterVo 数组，包含路由名称（path 首字母大写 + menuId）、路径、组件路径、Meta（标题、图标、缓存配置）、子路由

### 场景：权限标识加载
- Given 用户登录系统
- When Sa-Token 调用 StpInterface.getPermissionList()
- Then 系统从数据库查询该用户所有角色关联的菜单权限标识，如 ["system:user:list", "system:user:add", "system:user:edit"]

### 场景：删除被角色使用的菜单
- Given 菜单"用户管理"已被某个角色分配
- When 超级管理员尝试删除该菜单
- Then 系统返回"菜单已分配,不允许删除"

### 场景：路由冲突校验
- Given 系统已存在同级路由路径"user"
- When 超级管理员在同一父级下新建菜单，路由路径也设置为"user"
- Then 系统返回"路由名称或地址已存在"

## 6. 非功能需求
- getRouters 接口 MUST 在用户登录后即可调用，不需要额外权限校验
- 权限标识（perms）格式 MUST 符合正则 `^[a-zA-Z0-9:_*-]+$`（如 system:user:list）
- 菜单树构建 MUST 使用动态规划算法（TreeBuildUtils）避免递归导致的性能问题
- 所有写操作 MUST 使用 @RepeatSubmit 防重复提交，且只有超级管理员角色可操作
- 操作日志 MUST 使用 @Log 注解记录

## 7. 依赖
- SysRole（角色管理）- 角色通过 sys_role_menu 关联表分配菜单权限
- SysUser（用户管理）- 通过用户 → 角色 → 菜单链查询用户权限
- Sa-Token（权限认证）- 权限标识用于 @SaCheckPermission 注解的接口鉴权
