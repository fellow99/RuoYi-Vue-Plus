# 通知公告功能规格 (spec.md)

> 模块：009-notice | 状态：已实现 | 最后更新：2026-08-10

## 1. 模块概述

### 1.1 目的
通知公告管理模块用于系统管理员发布通知和公告信息。发布后的公告会通过 WebSocket/SSE 实时推送给所有在线用户，确保重要信息及时触达。

### 1.2 解决的问题
- 管理员需要一个界面来发布系统通知和公告
- 通知发布后需要在线用户能实时收到，而不是被动刷新页面查看
- 公告有不同类型（通知/公告），前端需要区分展示

### 1.3 范围
- ✅ 通知公告 CRUD
- ✅ 新增公告后通过 MessageService 实时推送在线用户
- ✅ 公告类型区分（通知/公告）
- ✅ 公告状态控制（正常/关闭）
- ❌ 用户已读状态追踪
- ❌ 用户端公告弹窗 UI

## 2. 用户故事
- 作为**管理员**，我可以发布一条系统公告，以便所有在线用户立即收到通知
- 作为**管理员**，我可以编辑或删除已发布的公告
- 作为**在线用户**，我在登录状态下能实时收到管理员推送的公告信息

## 3. 功能需求

- FR-009-001: 系统 MUST 支持分页查询通知公告列表，支持按标题、类型、创建人筛选
- FR-009-002: 系统 MUST 支持新增通知公告，发布后通过 MessageService 广播给所有在线用户
- FR-009-003: 系统 MUST 支持修改通知公告（修改不会再次推送）
- FR-009-004: 系统 MUST 支持单个和批量删除通知公告
- FR-009-005: 系统 MUST 支持公告类型区分（noticeType: 1=通知, 2=公告）
- FR-009-006: 系统 MUST 支持公告状态控制（status: 0=正常, 1=关闭）
- FR-009-007: 系统 MUST 在新增公告后自动获取通知类型标签（通过字典服务）

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| SysNotice | 通知公告表 | noticeId, noticeTitle, noticeType, noticeContent, status, remark |

> noticeType: 1=通知, 2=公告（字典 sys_notice_type）
> status: 0=正常（显示）, 1=关闭（隐藏）

## 5. 验收场景

### 场景：发布公告并推送给在线用户
- Given 管理员登录系统，有若干用户在线
- When 新增公告"系统维护通知"，类型=通知，状态=正常 → 提交
- Then 公告保存成功，所有在线用户通过 WebSocket/SSE 收到推送消息（标题、类型、摘要）

### 场景：关闭公告
- Given 存在一条状态为"正常"的公告
- When 管理员编辑公告，将状态改为"关闭" → 保存
- Then 公告状态更新，前端不再展示该公告

### 场景：按创建人搜索公告
- Given 系统中存在多条公告
- When 管理员在搜索框输入创建人用户名 → 查询
- Then 返回该创建人创建的所有公告列表

## 6. 非功能需求
- 公告推送 MUST 通过 MessageService 的 publishAll() 方法，支持 WebSocket 和 SSE 两种通道
- 推送消息 MUST 包含公告类型标签（通过字典服务获取）、标题、ID、内容、状态
- 推送消息 MUST 包含跳转路径（/system/notice?noticeId=X），用户点击可查看详情

## 7. 依赖
- MessageService（ruoyi-api, WebSocket/SSE 消息推送）— 公告实时广播
- DictService（ruoyi-api, 字典服务）— 获取公告类型标签
