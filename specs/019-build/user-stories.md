## 五、验收场景

### 场景 1：开发人员本地构建运行

**给定** 已安装 Java 17 和 Maven  
**当** 开发人员执行 `mvn clean package -DskipTests`  
**并且** 执行 `java -jar ruoyi-admin.jar`  
**那么** 应用启动成功  
**并且** 可以访问 `http://localhost:8080`

---

### 场景 2：运维人员部署服务

**给定** 已准备好 JAR 包  
**当** 运维人员执行 `./ry.sh start`  
**那么** 服务启动成功  
**并且** 日志输出到 `logs/` 目录  
**并且** 服务后台运行

---

### 场景 3：Docker Compose 一键部署

**给定** 已安装 Docker 和 Docker Compose  
**当** 运维人员执行 `docker-compose up -d`  
**那么** MySQL、Redis、应用、Nginx 全部启动  
**并且** 可以访问 `http://localhost`  
**并且** 数据持久化保存

---

### 场景 4：查看服务状态

**给定** 服务正在运行  
**当** 运维人员执行 `./ry.sh status`  
**那么** 显示 "is running"  
**并且** 显示进程 ID

---

### 场景 5：健康检查

**给定** 服务正在运行  
**当** 运维人员访问 `/actuator/health`  
**那么** 返回 JSON 响应  
**并且** status 为 "UP"  
**并且** 显示数据库和 Redis 状态

## 六、依赖与风险

### 依赖

- Java 17+
- Maven 3.6+
- Docker 20.x+
- MySQL 8.0+
- Redis 7.x+

### 风险

1. **环境差异**：不同环境配置不同
   - 缓解：使用多环境配置文件

2. **端口冲突**：端口被占用
   - 缓解：启动前检查端口

3. **资源不足**：内存或磁盘不足
   - 缓解：配置合理的 JVM 参数

4. **网络问题**：容器网络不通
   - 缓解：使用 Docker Compose 网络

## 七、最佳实践

### 7.1 构建最佳实践

- 本地开发使用 `mvn clean compile`
- 提交前使用 `mvn clean verify`
- 发布使用 `mvn clean package -DskipTests -Pprod`

### 7.2 部署最佳实践

- 开发环境使用脚本启动
- 测试环境使用 Docker Compose
- 生产环境使用 Kubernetes

### 7.3 监控最佳实践

- 配置健康检查端点
- 使用 ELK 收集日志
- 使用 Prometheus + Grafana 监控

### 7.4 安全最佳实践

- 生产环境关闭调试日志
- 使用环境变量存储敏感信息
- 定期更新依赖版本
