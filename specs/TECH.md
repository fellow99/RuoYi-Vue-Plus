## 一、技术栈概览

RuoYi-Vue-Plus v6.0.0 是针对分布式集群场景全方位重写的企业级快速开发平台，基于 **Spring Boot 4.1 + JDK 21** 构建。相比 v5，v6 移除了多租户支持，升级至 Spring Boot 4.1，新增 AI、LiteFlow、MQTT、MCP、消息推送、Elasticsearch 等模块。

### 架构模式
- **架构风格：** 前后端分离 + 插件化模块设计
- **后端架构：** Spring Boot 四层分层架构（Controller → Service → Mapper → Entity）
- **前端架构：** Vue3 + TypeScript + Element Plus（独立前端项目 plus-ui）
- **通信协议：** HTTP/HTTPS + RESTful API + WebSocket + SSE + MCP
- **数据格式：** JSON

## 五、技术选型理由

### 5.1 为什么选择 Spring Boot 4.1?
- **最新 LTS 基线：** JDK 21 LTS + 虚拟线程支持
- **性能飞跃：** 相比 2.x/3.x 性能大幅提升
- **AI 原生：** Spring AI 2.0 深度集成
- **Jetty 12：** Netty 底层，高并发高性能

### 5.2 为什么选择 Jetty 替代 Undertow?
- **Netty 底层：** 原生异步非阻塞，更强的并发处理能力
- **Spring Boot 推荐：** Spring Boot 4.x 主推 Jetty 作为默认容器
- **虚拟线程兼容：** 对 JDK 21 虚拟线程有更好的支持

### 5.3 为什么选择 Sa-Token + JWT？
- **功能齐全：** 登录、角色、权限、二级认证、HttpBasic 一站解决
- **低耦合：** 静态方法调用，不侵入业务代码
- **JWT 无状态：** 天然支持分布式集群 Token 验证

### 5.4 为什么选择 Redisson？
- **官方推荐：** Redis 官方推荐的 Java 客户端
- **功能全面：** 支持 Redis 90% 以上命令，分布式锁、限流、队列内置
- **性能优化：** 基于 Netty，底层优化规避不正确用法

### 5.5 为什么选择 SnailJob？
- **分布式原生：** 无需额外配置即可支持分布式
- **统一管理：** Web 管理中心、可视化操作
- **功能丰富：** 分片、重试、DAG 任务流、多数据库存储

### 5.6 为什么选择 Apache Fesod (EasyExcel 后继)？
- **Apache 基金会：** 官方孵化项目，长期稳定
- **插件化：** 框架扩展支持自动合并、字典翻译等
- **性能优秀：** 流式读写，低内存占用

### 5.7 为什么选择 Spring AI 2.0？
- **标准化：** 统一的多模型接口抽象
- **MCP 协议：** 内置 Model Context Protocol 支持
- **生态整合：** 与 Spring Boot 深度整合
