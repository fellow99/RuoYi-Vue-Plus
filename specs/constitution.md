# 宪法原则文档 (constitution.md)

**版本：** 6.0.0  
**最后更新：** 2026-08-10  
**项目：** RuoYi-Vue-Plus

## 一、项目开发原则

### 1.1 核心价值观

1. **简单优于复杂**
   - 代码要简洁易懂，避免过度设计
   - 优先使用简单方案，复杂方案需充分论证
   - 保持代码可读性，让新人能快速上手

2. **约定优于配置**
   - 遵循项目既定规范和约定
   - 减少不必要的配置项
   - 统一命名规范、目录结构、代码风格

3. **实用优于完美**
   - 解决实际问题优先
   - 避免过度优化和过早优化
   - 迭代改进，持续优化

4. **安全优于便利**
   - 安全考虑优先于使用便利
   - 输入验证、输出编码、权限控制
   - 不信任任何外部输入

### 1.2 架构原则

1. **插件化设计**
   - 模块之间低耦合高内聚
   - 功能以插件形式组织（ruoyi-common 子模块），按需引入
   - 避免模块间循环依赖

2. **分布式就绪**
   - 支持集群部署，无状态设计
   - 分布式锁（Lock4j + Redisson）、分布式任务调度（SnailJob）原生支持
   - Redisson 集中式会话管理

3. **扩展性优先**
   - 预留扩展点，支持自定义扩展
   - 接口化设计，支持实现替换
   - 注解驱动，支持行为定制

4. **前后端分离**
   - 前端独立项目（plus-ui），后端纯 API 服务
   - RESTful API 标准化接口设计
   - 统一 JSON 响应格式

### 1.3 开发流程原则

1. **需求先行** - 开发前明确需求和验收标准
2. **设计先行** - 复杂功能先设计后编码
3. **测试伴随** - 功能完成，测试完成
4. **文档同步** - 代码变更，文档同步

### 1.4 代码提交原则

1. **小步提交** - 每次提交解决一个问题
2. **规范提交** - 遵循 Conventional Commits 规范
3. **完整提交** - 提交包含所有相关文件
4. **及时提交** - 完成功能及时提交

## 二、代码规范原则

### 2.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 类名 | 大驼峰 PascalCase | `UserService`, `AuthController` |
| 方法/变量 | 小驼峰 camelCase | `getUserById`, `userName` |
| 常量 | 全大写下划线 | `MAX_RETRY_COUNT` |
| 包名 | 全小写点分隔 | `org.dromara.system.controller` |
| 数据库表 | 小写下划线，sys_ 前缀 | `sys_user`, `sys_role_menu` |
| 接口 | 大驼峰，I 前缀 | `ISysUserService` |
| 实现类 | 大驼峰 + Impl 后缀 | `SysUserServiceImpl` |
| 实体类 | 表名转大驼峰 | `SysUser`, `SysRole` |

### 2.2 分层规范

```
controller/     # 控制器层（ruoyi-system/ruoyi-admin），处理 HTTP 请求
   ↓
service/        # 业务逻辑层（接口 + 实现），事务控制
   ↓
mapper/         # 数据访问层（MyBatis-Plus Mapper），数据库操作
   ↓
database        # 数据库（MySQL / Oracle / PostgreSQL / SQLServer）
```

### 2.3 注释规范

1. **类注释** - 每个类必须有 JavaDoc 类注释，说明类的用途
2. **方法注释** - 公共方法必须有 JavaDoc 注释，说明参数、返回值、异常
3. **复杂逻辑** - 复杂业务逻辑必须有注释说明
4. **TODO 标记** - 未完成的功能使用 TODO 标记

### 2.4 代码风格

1. **Alibaba 规范** - 严格遵守 Alibaba Java 开发手册
2. **统一格式化** - 使用项目统一的代码格式化配置（.editorconfig）
3. **无警告提交** - 提交前消除所有编译警告
4. **Lombok 优先** - 使用 Lombok 注解简化样板代码

## 三、技术选型原则

### 3.1 技术选型标准

1. **成熟稳定** - 选择经过生产验证的技术
2. **社区活跃** - 选择社区活跃、文档完善的技术
3. **性能优先** - 在满足功能前提下选择性能更好的技术
4. **易于维护** - 选择易于理解、易于维护的技术

### 3.2 核心技术栈（v6）

| 类别 | 技术 | 选择理由 |
|------|------|----------|
| 权限认证 | Sa-Token + JWT | 轻量、功能全、易用性强、无状态 |
| ORM 框架 | MyBatis-Plus | 功能强大、插件丰富、学习成本低 |
| 缓存客户端 | Redisson | 基于 Netty、支持命令多、性能好 |
| Web 容器 | Jetty 12 | 基于 Netty、高性能、Spring Boot 4 默认 |
| 任务调度 | SnailJob | 分布式、功能完善、可视化 |
| 文件存储 | MinIO + RustFS | 分布式、支持 S3 协议、开源免费 |
| 工作流 | Warm-Flow | 轻量级、功能齐全、易集成 |
| AI 集成 | Spring AI 2.0 | 标准化接口、MCP 协议支持 |

## 四、安全原则

### 4.1 认证授权

1. **JWT 无状态认证** - Token 携带用户信息，服务端不存储会话
2. **权限注解控制** - 使用 `@SaCheckRole`, `@SaCheckPermission` 注解
3. **数据权限隔离** - 基于部门、角色的数据范围过滤（MyBatis-Plus 插件）
4. **客户端管理** - 支持多客户端动态授权（PC、小程序等）

### 4.2 数据安全

1. **输入验证** - 所有输入必须验证，使用 Validation 框架
2. **SQL 防注入** - 使用 MyBatis-Plus 参数化查询，禁止 SQL 拼接
3. **XSS 防护** - 输出编码，内置 XSS 过滤器
4. **敏感数据加密** - 密码 BCrypt 加密存储，敏感字段注解加解密

### 4.3 接口安全

1. **接口传输加密** - 使用动态 AES + RSA 加密请求 body
2. **接口幂等性** - 使用 `@Idempotent` 注解防止重复提交
3. **接口限流** - 使用 `@RateLimiter` 注解限制访问频率
4. **接口文档脱敏** - 生产环境关闭 SpringDoc 或增加认证

## 五、质量原则

### 5.1 代码质量

1. **Alibaba 规范** - 严格遵守 Alibaba Java 开发手册
2. **统一格式化** - 使用项目统一的代码格式化配置
3. **无警告提交** - 提交前消除所有编译警告
4. **单元测试** - 核心业务逻辑必须有单元测试

### 5.2 测试原则

1. **测试先行** - 复杂功能先写测试用例
2. **回归测试** - 修改后必须通过回归测试
3. **自动化测试** - 尽可能使用自动化测试（Maven Surefire）
4. **测试覆盖** - 核心功能测试覆盖率 > 80%

### 5.3 文档原则

1. **API 文档** - 所有接口必须有 SpringDoc 文档（基于 Javadoc）
2. **变更文档** - 重大变更必须更新文档
3. **部署文档** - 提供完整的 Docker 部署说明
4. **规范文档** - 维护 specs/ 目录下的完整规范文档

## 六、违反处理

### 6.1 代码审查

1. **PR 必审** - 所有代码提交必须经过 Code Review
2. **规范检查** - 使用检查清单确保符合规范
3. **问题记录** - 审查发现的问题必须记录并修复

### 6.2 违规处理

1. **轻微违规** - 指出问题，要求修改
2. **严重违规** - 打回重做，记录在案
3. **重复违规** - 团队通报，培训学习
