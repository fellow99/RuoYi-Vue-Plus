## 一、系统概述

### 1.1 系统定位

RuoYi-Vue-Plus 是针对 RuoYi-Vue 进行全方位重写的多租户快速开发框架，采用插件化架构设计，支持分布式集群与多租户场景。基于 Spring Boot 3.5 + JDK 17/21 构建，提供完善的权限管理、系统监控、代码生成等功能。

### 1.2 与 RuoYi-Vue 的差异

| 维度 | RuoYi-Vue | RuoYi-Vue-Plus |
|------|-----------|----------------|
| 前端框架 | Vue2/Vue3 + JS | Vue3 + TypeScript + Element Plus |
| 后端架构 | 模块化，耦合较高 | 插件化，解耦易扩展 |
| 权限认证 | Spring Security | Sa-Token |
| ORM 框架 | MyBatis (XML) | MyBatis-Plus (对象操作) |
| 缓存客户端 | Lettuce + RedisTemplate | Redisson |
| Web 容器 | Tomcat | Undertow |
| 序列化 | Fastjson | Jackson |
| 多租户 | 不支持 | 原生支持 |
| 分布式锁 | 不支持 | Lock4j + Redisson |
| 任务调度 | Quartz | SnailJob (分布式) |
| 文件存储 | 本地文件 | MinIO 分布式存储 |
| 数据脱敏 | 不支持 | 注解 + 序列化脱敏 |
| 数据加解密 | 不支持 | 注解 + 拦截器加解密 |
| 接口加密 | 不支持 | 动态 AES + RSA |
| 数据翻译 | 不支持 | 注解 + 动态翻译 |

### 1.3 目标用户

- **超级管理员** - 系统最高权限，管理所有租户
- **租户管理员** - 租户内最高权限，管理租户内部资源
- **普通管理员** - 部门或模块管理员，拥有部分管理权限
- **普通用户** - 日常业务操作、信息查询
- **开发人员** - 基于框架进行二次开发

### 1.4 核心价值

1. **快速开发** - 提供通用功能模块，减少重复开发
2. **权限完善** - 细粒度权限控制，支持数据权限和多租户
3. **易于扩展** - 插件化设计，支持功能扩展
4. **开箱即用** - 内置常用功能，配置即可使用
5. **分布式就绪** - 原生支持分布式场景

## 三、用户角色定义

### 3.1 角色分类

系统预置以下角色，支持自定义扩展。

| 角色名称 | 角色标识 | 角色描述 | 权限范围 |
|----------|----------|----------|----------|
| 超级管理员 | admin | 系统最高权限角色，管理所有租户 | 所有权限 |
| 租户管理员 | tenant_admin | 租户内最高权限 | 租户内所有权限 |
| 普通管理员 | common_admin | 部门或模块管理员 | 部分管理权限 |
| 普通角色 | common | 普通用户角色 | 按需分配的权限 |
| 自定义角色 | - | 用户自定义角色 | 按需分配 |

### 3.2 数据权限

| 数据范围 | 说明 | SQL 过滤条件 |
|----------|------|-------------|
| 全部数据权限 | 可查看所有数据 | 无过滤 |
| 自定义数据权限 | 按角色自定义数据范围 | `dept_id IN (custom_dept_ids)` |
| 本部门及以下数据权限 | 可查看本部门及下级部门数据 | `dept_id IN (dept_ancestors)` |
| 本部门数据权限 | 仅查看本部门数据 | `dept_id = current_dept_id` |
| 仅本人数据权限 | 仅查看本人数据 | `user_id = current_user_id` |

### 3.3 用户类型

| 用户类型 | 说明 |
|----------|------|
| sys_user | 系统用户（默认） |
| other | 其他用户类型（可扩展） |

## 四、多租户设计

### 4.1 租户模型

RuoYi-Vue-Plus 采用共享数据库、共享表结构的多租户架构，通过 `tenant_id` 字段实现数据隔离。

### 4.2 租户隔离方式

| 隔离级别 | 说明 |
|----------|------|
| 数据库隔离 | 每个租户独立数据库（可选） |
| Schema 隔离 | 每个租户独立 Schema（可选） |
| 字段隔离 | 通过 tenant_id 字段区分（默认） |

### 4.3 租户相关实体

| 实体 | 说明 |
|------|------|
| SysTenant | 租户信息 |
| SysTenantPackage | 租户套餐 |
| SysClient | 客户端配置 |

### 4.4 租户字段设计

所有业务表必须包含以下租户相关字段：
- `tenant_id` - 租户 ID（字符串类型）
- 通过 MyBatis-Plus 多租户插件自动注入过滤条件

## 五、核心业务流程

### 5.1 用户登录流程

```
用户输入账号密码 → 验证码校验 → 租户校验 → 密码验证 
→ 生成 JWT Token → 返回用户信息和权限 → 登录完成
```

### 5.2 权限校验流程

```
请求到达 → 解析 Token → 获取用户信息 → 校验登录状态 
→ 校验角色权限 → 校验数据权限 → 执行业务逻辑
```

### 5.3 多租户数据访问流程

```
请求到达 → 解析租户 ID → 注入租户过滤条件 → 执行 SQL 
→ 返回租户专属数据
```

### 5.4 代码生成流程

```
选择数据表 → 配置生成规则 → 预览代码 → 下载/生成到项目
```
