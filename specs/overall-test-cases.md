## 二、认证模块测试用例（公共）

### TC-AUTH-001：密码登录
- **前置条件：** 存在有效用户账号
- **步骤：** 输入用户名、密码、验证码 → 点击登录
- **预期：** 登录成功，返回 Token，跳转首页

### TC-AUTH-002：密码错误
- **前置条件：** 存在有效用户账号
- **步骤：** 输入正确用户名、错误密码
- **预期：** 登录失败，提示"密码错误"，重试次数 +1

### TC-AUTH-003：账号锁定
- **前置条件：** 用户已被锁定（连续 5 次密码错误）
- **步骤：** 输入被锁定账号密码
- **预期：** 提示"账号已锁定"

### TC-AUTH-004：验证码刷新
- **步骤：** 点击验证码图片
- **预期：** 验证码刷新

### TC-AUTH-005：退出登录
- **前置条件：** 已登录
- **步骤：** 点击退出登录
- **预期：** Token 失效，跳转登录页

## 三、通用 CRUD 测试模式

以下模式适用于所有系统管理模块（002-009）：

### TC-CRUD-001：分页列表查询
- 进入模块列表页 → 验证默认分页显示 → 输入查询条件 → 点击搜索 → 验证过滤结果

### TC-CRUD-002：新增记录
- 点击新增按钮 → 填写表单 → 点击确定 → 验证列表出现新记录

### TC-CRUD-003：修改记录
- 在列表中选择记录 → 点击修改 → 修改字段 → 保存 → 验证修改生效

### TC-CRUD-004：删除记录
- 选择记录 → 点击删除 → 确认 → 验证记录已移除

### TC-CRUD-005：导出
- 设置筛选条件 → 点击导出 → 验证下载 Excel 文件

### TC-CRUD-006：必填校验
- 点击新增 → 不填必填项 → 点击确定 → 验证必填提示

## 四、非功能测试场景

### TC-NF-001：并发登录
- 同一账号在两个浏览器同时登录
- 预期：均可登录，各自独立会话

### TC-NF-002：Token 过期
- 等待 Token 过期后访问 API
- 预期：返回 401，前端跳转登录页

### TC-NF-003：接口限流
- 短时间内多次调用限流接口
- 预期：触发限流，返回错误提示

### TC-NF-004：XSS 防护
- 在文本输入框输入 `<script>alert(1)</script>`
- 预期：XSS 脚本被过滤或编码
